# Flat watcher — новые квартиры в Telegram

Каждые ~10 минут (ночью с 01 до 06 — раз в час) GitHub Actions проверяет поиск аренды на трёх сайтах и присылает в Telegram только новые объявления: название, цену, район и ссылку.

| Сайт | Что смотрим | Как парсим |
|---|---|---|
| topreality.sk | стр. 1–2, сортировка «najnovšie» (`sort=id_desc`) | карточки `div.estate[data-idinz]` |
| reality.bazos.sk | стр. 1, `order=4` (новые, без TOP) | карточки `div.inzeraty`, ID из `/inzerat/<id>/` |
| nehnutelnosti.sk | стр. 1, `order=NEWEST` | JSON-LD списка на странице + район из карточки |

Фильтры взяты из твоих ссылок, с тремя поправками:
- **topreality:** твоя ссылка вела на *2-ю* страницу (`vyhladavanie-nehnutelnosti-2.html`) с сортировкой по умолчанию. Я поменял её на 1-ю и 2-ю страницы с сортировкой «сначала новые». На 1-й странице сверху 12 платных TOP-объявлений, поэтому одной страницы мало.
- **bazos:** в ссылке не было цены, и приходили квартиры за 1 200–1 750 €. Добавил `cenado=901`, как на остальных сайтах.
- **nehnutelnosti:** ссылка как есть.

Ссылки поиска лежат в начале `watcher.py` в `SEARCH_URLS`. Чтобы поменять фильтры, настрой поиск на сайте и вставь туда новый URL. Сортировку «сначала новые» оставь.

## 1. Создать бота в Telegram

1. Открой в Telegram **@BotFather** и отправь `/newbot`.
2. Введи имя бота (любое, например `Byty Bratislava`), затем username, который заканчивается на `bot` (например `pablo_byty_bot`).
3. BotFather пришлёт **токен** вида `1234567890:AAH...`. Это пароль от бота, никому его не показывай и не коммить в репозиторий.
4. Найди своего бота по username, нажми **Start** и напиши ему что-нибудь, например «привет». Без этого бот не сможет тебе писать.

## 2. Узнать chat_id

Самый простой способ: открой в браузере ссылку, подставив свой токен:

```
https://api.telegram.org/bot<ТОКЕН>/getUpdates
```

В ответе найди `"chat":{"id":123456789,...}`. Число `123456789` и есть твой **chat_id**.
Если ответ `{"ok":true,"result":[]}`, значит, ты ещё не написал боту: напиши и обнови страницу.

Можно и через скрипт:

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN="1234567890:AAH..."      # Windows PowerShell: $env:TELEGRAM_BOT_TOKEN="..."
python watcher.py --chat-id
```

> Хочешь получать объявления в группу (например, вместе с соседом по квартире)? Добавь бота в группу, напиши там сообщение и повтори шаг выше. chat_id группы начинается с минуса: `-100…`.

## 3. Проверить локально (по желанию)

```bash
python watcher.py --print     # что сейчас на страницах поиска
export TELEGRAM_CHAT_ID="123456789"
python watcher.py --test      # тестовое сообщение в Telegram
python -m unittest discover tests   # тесты парсеров
```

## 4. Залить на GitHub

1. Создай на GitHub новый **публичный** репозиторий, например `flat-watcher`. Для публичных репозиториев Actions бесплатны без лимита минут.
2. Залей туда все файлы этой папки вместе со скрытой папкой `.github`:
   ```bash
   cd flat-watcher
   git init && git add . && git commit -m "Flat watcher"
   git branch -M main
   git remote add origin https://github.com/<твой-логин>/flat-watcher.git
   git push -u origin main
   ```
3. В репозитории открой **Settings → Secrets and variables → Actions → New repository secret** и добавь два секрета:
   - `TELEGRAM_BOT_TOKEN`: токен от BotFather;
   - `TELEGRAM_CHAT_ID`: твой chat_id.

   Секреты не видны ни в коде, ни в логах, даже в публичном репозитории.

## 5. Запустить

1. Вкладка **Actions** → слева **Flat watcher** → **Run workflow**.
2. Первый запуск ничего не рассылает. Он запоминает все текущие объявления и присылает три сообщения «Начал следить за …». В репозитории появится коммит с `seen.json`.
3. Дальше всё работает само по расписанию. Приходят только объявления, которых не было при прошлой проверке.

## Как это устроено

- **`seen.json`** хранит ID уже виденных объявлений по каждому сайту. После каждого прогона с новыми объявлениями workflow коммитит его обратно в репозиторий. ID старше 90 дней удаляются, чтобы файл не рос. Если удалить `seen.json`, следующий запуск снова «тихо» запомнит всё текущее.
- **Если сайт сломался** (не грузится или поменялась вёрстка), остальные сайты продолжают работать. После 6 неудачных прогонов подряд (~1 час) бот один раз пришлёт предупреждение, а когда сайт починится — «снова работает».
- **Лимит:** не больше 25 сообщений за прогон, остальное придёт в следующий раз. Это защита от флуда, если резко поменяешь фильтры.
- **`MAX_PRICE`:** дополнительный фильтр по цене, если какой-то сайт игнорирует фильтр в URL. Раскомментируй строку в `.github/workflows/watch.yml`.

## Что может пойти не так

- **Расписание опаздывает.** GitHub не гарантирует точное время cron: в часы пик запуск может задержаться на 5–20 минут. Для квартир это обычно не критично.
- **Расписание выключилось.** В публичном репозитории GitHub отключает cron, если в репо 60 дней нет активности. Коммиты `seen.json` считаются активностью, так что при живом рынке это не грозит. Если всё же отключится, на вкладке Actions появится кнопка **Enable workflow**.
- **Ошибка `Permission denied` / 403 при `git push`.** Открой Settings → Actions → General → Workflow permissions и выбери **Read and write permissions**.
- **Сайт отдаёт 403 из GitHub Actions** (некоторые сайты блокируют IP дата-центров). В логах будет `❌ <сайт>: … 403`, а через час придёт предупреждение в Telegram. Остальные сайты продолжат работать. Обходной путь: запускать скрипт на своём компьютере или Raspberry Pi по cron (`*/10 * * * * cd ~/flat-watcher && python3 watcher.py`).
- **Поменялась вёрстка.** Парсеры лежат в `watcher.py` (`parse_topreality`, `parse_bazos`, `parse_nehnutelnosti`). Тесты в `tests/` сделаны на реальной разметке от 19.11.2026: если сайт поменяется, сохрани новую страницу в `tests/fixtures/` и поправь селекторы.
